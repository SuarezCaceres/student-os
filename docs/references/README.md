# Referencias

Material de consulta: guías, ejemplos de código, enlaces y documentación oficial. A diferencia de las reglas, **no es obligatorio**: el agente lo consulta cuando tiene una duda de *cómo* hacer algo.

```
references/
  frontend/   guías del framework, patrones de UI, ejemplos de componentes
  backend/    patrones de API, ejemplos de servicios, documentación de la BD
  testing/    ejemplos de pruebas bien escritas, guías de la herramienta de E2E
```

Consejos:
- Un archivo por tema, con un nombre descriptivo (`formularios-con-validacion.md`, no `notas.md`).
- Al principio de cada archivo, una línea que diga de qué trata y cuándo es útil.
- Si un material se vuelve obligatorio, conviértelo en regla en `docs/rules/`.
- Si es un procedimiento que se repite, conviértelo en skill en `.agents/skills/`.
